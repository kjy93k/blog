### **들어가며**

  

구인 공고를 보다 보면 요즘 자주 보이는 문구가 있다.

**“React, React Native, WebView 경험 우대”**

**“웹과 앱 둘 다 다룰 수 있는 개발자”**

  

웹만 해오던 입장에서 React Native는 한 번쯤 배워야지 하고 미뤄둔 기술이었다.

그런데 이제는 선택이 아니라, 기본 옵션처럼 달려 있다.

---

### **회사들도 앱으로 가는 추세**

  

지금 운영 중인 heyb도 사실 추후에는 WebView를 얹어 앱까지 만들어볼 생각이었다.

예전에 이랜드옥션 프로젝트를 할 때도, 웹으로 경매 서비스를 먼저 구축하고

잘 되면 앱으로 확장할 계획이 있었는데 결국 일정과 리소스 때문에 못 했었다.

  

이런 사례는 거의 모든 팀이 비슷하다.

처음엔 웹으로 가볍게 MVP를 만들고,

서비스가 커지면 유저 편의성을 위해 앱으로 자연스럽게 확장한다.

  

요즘엔 이게 너무 당연한 흐름이라

초반부터 **“웹 + 앱 동시 유지보수 가능한 구조로 가자”** 는 이야기가 프로젝트 초기에 꼭 나온다.

---

### **WebView + React Native**

  

처음부터 앱 전체를 네이티브로 만드는 건 돈과 시간이 너무 많이 든다.

그래서 대부분은 기존 웹을 최대한 살리고,

필수적인 화면이나 푸시 알림 같은 기능만 React Native로 감싼다.

  

이게 바로 **WebView + React Native** 구조다.

하이브리드 앱이라고 부르기도 한다.

  

결국 실무에서 이 구조를 다뤄보지 않으면,

빌드나 배포 단계에서 꼭 막히게 된다.

---

###  **흔히 듣게 되는 요구사항**

- 기존 웹을 스토어에 앱으로 올려달라는 요청
    
- WebView로 감싸더라도 푸시 알림은 앱으로 처리해야 하는 상황
    
- 사진 촬영, 위치 정보 등 브라우저에선 불편한 기능을 앱에서 처리하고 싶어함
    
- 한 팀이 웹과 앱을 동시에 유지보수할 수 있는 구조 요청
    

  

이 모든 걸 안전하게 하려면 React Native를 조금이라도 알고 있어야 한다.

---

### **조금 늦었지만, 지금이 딱 좋다**

  

처음엔 Expo 강의를 따라하면서 커뮤니티 앱 정도는 만들어볼 수 있게 됐다.

덕분에 React Native 구조와 Expo의 빠른 개발 흐름을 대충 감 잡았다.

  

이제는 CLI로 넘어가서 직접 빌드 구조를 만지고 싶어졌다.

지금은 맛집 지도 앱 강의를 보며 React Native CLI로 만들어보려한다.

실무에서 해보면 좋을만한 경험을 쌓ㅇ지도 연동부터 백엔드(NestJS) 개발,

  

안 해본 걸 다 경험해봐야 나중에 실무에서 실수를 줄일 수 있을 것 같았다.

사실 백엔드도 제대로 배워보고 싶었는데 이번에 같이 해보자는 마음이다.

  

기기 배포는 아직 개발자 계정이 없어서 직접 못 하고 있지만,

기본 흐름은 정리해두고 나중에 heyb에서 앱 만들 땐 바로 써먹을 계획이다.

  

마지막으로, 이렇게 배우고 정리한 내용을

현재 RN과 WebView로 앱을 유지보수하는 실무자들에게 직접 물어보고

요즘 트렌드에 맞게 다듬어두려고 한다.

  

조금 늦은 만큼, 제대로 해두면 덜 헤맬 거라고 믿는다.
